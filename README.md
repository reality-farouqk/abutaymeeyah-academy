# Abu Taymeeyah Academy — Website

A Next.js (App Router) + TypeScript + Tailwind CSS website for Abu Taymeeyah
Academy for Qur'anic Memorisation and Training, built from the provided site
map, flyer, and logo.

## Getting started

```bash
npm install
npm run dev
```

Then open http://localhost:3000.

To build for production:

```bash
npm run build
npm run start
```

## What's included

- **Home** — hero, about preview, six programme cards, "why choose us,"
  admissions banner, testimonials, gallery preview, closing CTA.
- **About** — story, mission, vision, core values, teacher grid (all with
  the academy's exact mission/vision text; story and teacher bios are
  placeholders).
- **Programmes** — a detail section for each of the six class types
  (Beginners, Intermediate, Advanced, Private, Muraajah, Private Tajweed).
- **Admissions** — the 5-step admission process, a fees table (payment
  cadence only, amounts pending), and a full registration form.
- **Gallery** — categorized placeholder grid (Events, Students, Graduation,
  Competitions, Memorization Sessions, Islamic Programs).
- **Contact** — phone, email, WhatsApp link, contact form, map placeholder.
- **Enroll Now** — a 4-step enrollment wizard: choose programme → register →
  pay → confirmation.

## Payments

The Enroll flow supports Paystack and Flutterwave. Both API routes fall back
to a "demo mode" (simulated success) whenever their secret key env var is
missing, so the site works out of the box before you add real credentials.

To go live with Flutterwave, set these in `.env.local` (copy `.env.example`
to start):

```
FLUTTERWAVE_CLIENT_ID=...
FLUTTERWAVE_SECRET_KEY=...
FLUTTERWAVE_ENCRYPTION_KEY=...
```

`FLUTTERWAVE_SECRET_KEY` is used by `app/api/payment/flutterwave/initialize`
and `.../verify` to call the Flutterwave v3 REST API with a Bearer token.
`FLUTTERWAVE_CLIENT_ID` isn't used yet — it's only needed if this app later
moves to Flutterwave's OAuth-based v4 API. `FLUTTERWAVE_ENCRYPTION_KEY`
also isn't used — that's a v2/inline-checkout credential for client-side
card encryption, unrelated to this server-redirect flow. Both are kept in
`.env.local` for reference only.

### Webhook (recommended for production)

`app/api/payment/flutterwave/webhook` is a server-to-server endpoint that
Flutterwave calls directly when a payment completes — unlike `/verify`,
it doesn't depend on the customer's browser making it back to your site,
so it catches payments that the client-side flow would otherwise miss
(closed tab, dropped connection, failed redirect).

To enable it:

1. In the Flutterwave dashboard, go to **Settings → Webhooks**.
2. Set the webhook URL to `https://<your-domain>/api/payment/flutterwave/webhook`.
3. Choose your own random string as the **Secret Hash** and save it there.
4. Put that exact same string in `.env.local` as `FLUTTERWAVE_SECRET_HASH`.

That secret hash is something *you* invent — Flutterwave doesn't generate
or send it to you — and it's distinct from all three credentials above.
The endpoint verifies every incoming request against it before trusting
the payload, then re-confirms the transaction server-side via Flutterwave's
`/verify` API (never trusting the webhook body's amount/status directly)
before marking a registration as paid.

On your hosting provider (Vercel, etc.), add the same variables under
Project Settings → Environment Variables instead of committing `.env.local`.

**Security note:** since these keys were shared in a chat, treat them as
potentially exposed — consider rotating the Flutterwave secret key from
your Flutterwave dashboard (Settings → API) once you're ready to go live,
so only the new key ever touches your deployed environment.

## SEO

- **Domain:** `lib/site-config.ts` has a placeholder `SITE_URL` (no real domain
  exists yet). Everything below is derived from it — either edit that one
  line, or set `NEXT_PUBLIC_SITE_URL` in your hosting provider's environment
  variables once you have a real domain. Nothing else needs to change.
- **Favicon:** generated from `public/logo.jpg` — `app/favicon.ico` (legacy
  browsers), `app/icon.png` and `app/apple-icon.png` (modern browsers/iOS).
  Next.js wires these into `<head>` automatically; no code references them.
- **Metadata:** every page now has a unique title and description
  (`app/layout.tsx` sets sitewide defaults + a `%s | Abu Taymeeyah Academy`
  title template; each page overrides `title`/`description`/`canonical`).
- **robots.txt & sitemap.xml:** generated by `app/robots.ts` and
  `app/sitemap.ts`. The admin panel (`/admin`), the enroll wizard
  (`/enroll`), and the status lookup (`/admissions/status`) are excluded —
  they're transactional/internal, not content worth indexing.
- **Social share image:** `app/opengraph-image.tsx` / `app/twitter-image.tsx`
  generate a branded 1200×630 image on the fly (navy gradient + logo) for
  link previews on WhatsApp, Twitter/X, Facebook, etc.
- **Structured data:** `app/layout.tsx` includes JSON-LD
  (`EducationalOrganization`) so search engines can understand the academy's
  name, contact info, and description directly.

Once you have a real domain, it's worth submitting the sitemap
(`https://<your-domain>/sitemap.xml`) to Google Search Console and Bing
Webmaster Tools — that's outside what code can do for you.

## Design system

- **Colors:** deep navy (`#0F1E3D`), muted antique gold (`#C6942F`), pale
  sky-blue mist (`#EEF2F9`), near-white paper (`#FBFCFE`).
- **Type:** Amiri (display/serif, Arabic-rooted) for headings, Work Sans for
  body copy, IBM Plex Mono for labels, numbers, and step markers.
- **Signature motif:** a pointed mosque-arch shape (echoing the academy's
  own logo mark) used to frame images, cap programme cards, and mark
  numbered steps. Defined once in `components/ArchDefs.tsx` as reusable SVG
  clip-paths (`.arch-clip`, `.arch-clip-wide`).

## Photography

Real Qur'an, mosque, and study-session photography has been added throughout
the site (hero backgrounds on About/Programmes/Admissions/Enroll/Contact, the
Home page gallery preview, and the full Gallery page). All of it is sourced
from **Pexels** (free for commercial use, no attribution required — see
https://www.pexels.com/license/) and is defined in one place:
`lib/stock-images.ts`. Three categories are covered — `quranPhotos`,
`mosquePhotos`, and `learningPhotos` — each an array of `{ src, alt, credit }`
you can freely reorder, trim, or swap out.

The Gallery page's **Events**, **Graduation**, and **Competitions** sections
are left as placeholders on purpose — using generic stock photos there would
misrepresent the academy's actual events, so those should only be filled with
real photography once the academy provides it. The "Meet Our Teachers" grid
on the About page is left as a placeholder for the same reason.

To swap in the academy's own photography later: drop files into `public/`,
then replace the relevant `src` in `lib/stock-images.ts` (or the direct
`<Image>` calls in `app/gallery/page.tsx`) with local paths, e.g. `/gallery/photo-1.jpg`.
